# content 작업 규칙

- 상위 철학과 모듈화 판단 기준은 `docs/development-philosophy.md`를 따른다.
- `content/` 전체를 먼저 읽지 않는다.
- 먼저 [../docs/feature-routing.md](../docs/feature-routing.md)에서 primary feature를 고른 뒤 `content/features/<feature>/AGENTS.md`부터 읽는다.
- `content/main.js`, `content/panel.js`, `content/hosted-panel-bridge.js`는 feature-local 파일과 owned-shared만으로 해결되지 않을 때만 읽는다.
- 현재 `1.0.0` 확장 번들은 panel을 `content/panel-v2-composition-controller.js`로만 부팅한다. `backup/legacy-panel/panel-composition-controller.js`, `backup/legacy-panel/panel-action-controller.js`, `backup/legacy-panel/panel-meeting-controller.js`, `backup/legacy-panel/meeting-manager.js`는 활성 bundle이 아니라 legacy reference/source로만 본다.
- 현재 `1.0.0` 활성 bundle과 공유 계약이 더 이상 쓰지 않는 legacy panel 코드는 `content/*` 안에 계속 섞어 두지 않는다. 다음 정리 기본값은 `backup/legacy-panel/*`로 격리해 참고본으로만 남기는 것이다.
- panel shell 변경은 먼저 `content/main.js`, `content/panel-v2-composition-controller.js`, `content/panel-v2-shell-bridge.js`, `content/panel-console-trace.js`, `content/panel-host-runtime.js`, `content/panel-host-bridge.js`, `content/panel-host-view.js`, `content/page-capability-router.js`, `content/panel.js`, `content/hosted-panel-bridge.js`, `content/route-state-controller.js`, `content/route-watch-controller.js`, `content/route-sync.js`, `content/panel-v2-prompt-controller.js`의 책임 경계를 확인하고 시작한다.
- `content/main.js`는 panel shell의 composition root로만 두고, 현재 활성 controller graph 조립과 초기 state 조립은 `content/panel-v2-composition-controller.js`가 맡는다. paused/tool-surface/error/debug helper, active conversation bridge, panel-local provider identity sync는 같은 v2 composition에 두고, tool 전환/query/handle 저장을 포함한 open/visibility/surface/bootstrap/render bridge는 `content/panel-v2-shell-bridge.js`로 모은다. v2 prompt tool shell/controller wiring은 `content/panel-v2-prompt-controller.js`가 맡되 active shell 계약 이름도 legacy `panelPromptController` 대신 `promptShellController`로 유지한다. 책임은 review float와 review-triggered handoff/prompt-tab persistence까지만 남기고, generic `prompts/store` tool 선택이나 hosted-owned prompt tab/search/library/store/editor state mirror, store load/storage/sync sidecar는 더 이상 extension prompt controller나 route hydration에 두지 않는다. legacy prompt shell reference는 `backup/legacy-panel/panel-prompt-controller.js`, legacy bookmark/runtime/debug reference는 `backup/legacy-panel/panel-bookmark-controller.js`, `backup/legacy-panel/panel-runtime-controller.js`, `backup/legacy-panel/panel-debug-controller.js`, 공용 route 상태/route watcher 책임은 전용 controller에 누적한다.
- panel shell 현재 baseline은 `content/main.js`(state 생성 + v2 composition bootstrap), `content/panel-v2-composition-controller.js`(v2 controller graph 조립), `content/panel-v2-shell-bridge.js`(tool/open/visibility/surface/bootstrap/render bridge), `content/panel-console-trace.js`(top console trace policy), `content/frame-proxy-helper.js`(local hosted panel frame proxy resolver), `content/panel-host-runtime.js`(iframe target/status/handshake/render batching), `content/panel-host-bridge.js`(hosted bridge endpoint + page event emit), `content/panel-host-view.js`(host markup + handle interaction), `content/page-capability-router.js`(browser-only page capability 구현), `content/panel.js`(host element lifecycle + helper wiring), `content/hosted-panel-bridge.js`(hosted postMessage contract + top-panel request helper)로 본다.
- active content root inventory도 `composer(.js/.css)`, `dom.js`, `provider-identity-sensor.js`, `frame-proxy(.html/.js/helper)`, `page-capability-router.js`, `hosted-panel-bridge.js`, `panel-console-trace.js`, `panel-host-*`, `panel-v2-*`, `panel.js`, `panel.css`, `route-*`, `main.js`, `meeting-workspace-bridge.js`로 고정한다. 새 content runtime asset이 필요하면 먼저 현재 manifest lane에 실제 필요한 browser-only surface인지 확인하고, 추가가 맞으면 `contracts/extension-contract.json`과 `scripts/verify-contracts.js`를 함께 갱신한다.
- manifest browser privilege surface도 임의로 넓히지 않는다. `permissions`, `host_permissions`, `extension_pages frame-src`, meeting workspace bridge match, frame proxy web-accessible match는 `contracts/extension-contract.json`과 `scripts/verify-contracts.js`가 같이 잠그므로, 새 브라우저 권한이나 새 origin이 정말 필요할 때만 contract와 manifest를 같은 작업에서 함께 갱신한다.
- stable page capability 구현은 `content/page-capability-router.js` 한곳에만 둔다. `content/hosted-panel-bridge.js`는 `page/runtime/panel` 도메인 request dispatch만 맡고, DOM 읽기/클립보드/debug/trace 같은 실제 browser-only capability 로직은 page router로만 유지한다.
- panel console trace 정책과 snapshot trace payload helper는 `content/panel.js` 안에 다시 섞지 말고 `content/panel-console-trace.js`에서 유지한다. iframe target/status/handshake/render batching은 `content/panel-host-runtime.js`, hosted bridge endpoint와 page event emit은 `content/panel-host-bridge.js`, host markup과 handle drag/click은 `content/panel-host-view.js`에 두고, `panel.js`는 이 helper들을 주입받아 host element lifecycle만 유지한다.
- 현재 `content/hosted-panel-bridge.js`의 active request helper는 v2 hosted panel이 실제로 쓰는 `panel-chrome-sync`, runtime/page contract만 유지한다. conversation copy/jump/search와 top-level tool 선택은 hosted ownership에서 `page.adapter.v2` + `storage.write-ui-preferences`로 직접 처리하고, hosted close/Escape/external-handle open state는 `panel-chrome-sync`로 parent DOM에만 반영한다. legacy `meeting-action`, `release-action`, `tool-summary-sync`, `toggle-panel`, prompt action request path는 active `1.0.0` bundle의 보존 대상이 아니다.
- active hosted runtime broker는 `background/panel-runtime-capability-router.js`와 `background/panel-runtime-invoke.js`로 나눈다. router는 browser-only privileged capability 구현만 소유하고, invoke shim은 hosted panel request를 router에 dispatch하는 역할만 맡는다. generic tab/open-url browser adapter는 `background/browser-capability.js`, Functions endpoint family + lane-aware local/prod runtime config는 `background/functions-runtime-config.js`, panel auth/access-token/prompt runtime resolver는 `background/panel-session-capability.js`, hosted meeting workspace 쪽 browser-only open/share/auth/probe 구현은 `background/meeting-workspace-capability.js`로 분리하고, `background/service-worker.js`는 active top-level message gate + helper wiring만 유지한다. live v2 panel에서 필요한 stable runtime capability는 `storage.read-panel-state`, `storage.write-ui-preferences`, `auth.issue-panel-session`, `functions.invoke-endpoint`, `browser.open-url`, `meeting.workspace.open`, `meeting.result.open`, `meeting.share.create`, `meeting.share.revoke`로 제한하고, dormant storage read/write mutation이나 feature별 ad-hoc runtime action은 backup/reference 이유가 아니면 다시 열지 않는다. active background top-level message surface도 늘리지 말고 `inova-panel:invoke`와 hosted meeting workspace의 `authorize/probe` bridge만 유지한다.
- active background root inventory도 `browser-capability.js`, `cloud-api-client.js`, `functions-runtime-config.js`, `inova-auth-client.js`, `meeting-workspace-capability.js`, `panel-auth-cache.js`, `panel-runtime-capability-router.js`, `panel-runtime-invoke.js`, `panel-session-capability.js`, `service-worker.js` 열 파일로 고정한다. 새 background helper가 필요하면 먼저 기존 capability/router/module 안에 책임을 넣을지 검토하고, 정말 새 브라우저 권한 경계가 생길 때만 `contracts/extension-contract.json`과 `scripts/verify-contracts.js`를 함께 갱신한다.
- active hosted page adapter도 feature별 임시 action 문자열을 계속 늘리지 않는다. 새 hosted 기능은 가능하면 `conversation.read-state`, `conversation.jump-item`, `composer.read-state`, `composer.apply-text`, `clipboard.write-text`, `debug.read-state`, `debug.set-enabled`, `debug.copy-log`, `debug.clear-log`, `trace.log` 같은 capability-shaped action 위에서 해결한다. active 호출부를 같은 작업에서 canonical action으로 옮겼다면 old action alias를 남겨 다음 cleanup으로 미루지 말고 그 자리에서 같이 제거한다.
- active hosted capability 목록은 설명만 문서에 두지 않는다. canonical page/runtime action은 `contracts/extension-contract.json`과 `scripts/verify-contracts.js`가 같이 고정해야 하며, 새 hosted 기능을 만들 때는 먼저 그 카탈로그 안의 조합으로 해결 가능한지 확인한다. 새 browser capability가 정말 필요할 때만 contract와 extension 구현을 함께 늘린다.
- `scripts/verify-browser-only-boundary.js`는 active extension이 다시 feature/network ownership을 빨아들이지 못하게 하는 기본 가드다. direct `fetch`, `chrome.tabs`, `chrome.cookies`, `chrome.storage`, page `localStorage`, panel `sessionStorage`는 계약에 선언된 adapter file에서만 허용하고, thin `content/*`/`popup/*` shell이나 generic shared core가 raw Functions endpoint family 이름이나 Firebase SDK bootstrap을 다시 들면 실패하게 유지한다.
- active page-owned browser sensor도 `shared/*`에 남기지 않는다. i-Nova page localStorage에서 사용자 식별을 읽는 센서는 `content/provider-identity-sensor.js`에 두고, `shared/*`는 browser-agnostic cache/state helper만 유지한다.
- active panel host 전용 browser adapter도 `shared/*`에 남기지 않는다. local hosted panel을 `content/frame-proxy.html` wrapper로 감싸는 frame proxy resolver는 `content/frame-proxy-helper.js`에 두고, `shared/*`는 여러 surface가 같이 쓰는 core helper만 유지한다.
- active `shared/storage.js`는 generic local state/settings/ui-preferences/provider-identity-cache/product-lane migration core만 유지한다. inactive release/meeting storage accessor는 active shared core에 남겨 두지 말고 `backup/legacy-panel/shared/legacy-storage-accessors.js` 같은 backup-only helper로 격리한다.
- active `shared/constants.js`도 dormant release/meeting storage key/default contract를 계속 들고 있지 않는다. active constants는 live browser shell 기본값만 유지하고, inactive release/meeting storage schema는 backup helper가 자기 기본값을 직접 들도록 둔다.
- active `shared/constants.js`와 `shared/storage.js`는 dormant `promptLibrary` local storage schema도 계속 들고 있지 않는다. active prompt lane은 Firestore/hosted state를 정본으로 보고, legacy prompt local cache schema와 import/export helper는 `backup/legacy-panel/shared/prompt-storage.js`, `backup/legacy-panel/shared/prompt-library.js` reference가 직접 가진다.
- active shared root는 dormant prompt store taxonomy/helper도 계속 들고 있지 않는다. legacy prompt store normalization helper는 `backup/legacy-panel/shared/prompt-store.js`에 둔다. active hosted/functions store lane은 deploy root가 달라 `hosting/extension-v2/panel/prompt-store-model.js`와 `functions/shared/prompt-store-model.js` copy를 둘 다 두고, `scripts/verify-prompt-store-model.js`가 동일성과 Functions 위임을 잠근다.
- active shared root는 background-only auth/cloud helper도 계속 들고 있지 않는다. i-Nova access token refresh는 `background/inova-auth-client.js`, Functions-backed cloud POST helper는 `background/cloud-api-client.js`가 맡고, `shared/*`는 content/popup/background가 같이 쓰는 browser-agnostic core만 유지한다.
- active shared root는 background-only Functions endpoint family와 lane-specific endpoint override도 계속 들고 있지 않는다. `shared/firebase-config.js`는 hosting/panel/meeting target과 browser-agnostic config만 유지하고, Functions endpoint map과 local/prod runtime endpoint resolution은 `background/functions-runtime-config.js`가 맡는다.
- active shared root inventory는 `shared/constants.js`, `shared/firestore-collections.js`, `shared/firebase-config.js`, `shared/product-lane.js`, `shared/provider-identity-cache.js`, `shared/session.js`, `shared/storage.js` 일곱 파일로 고정한다. 새 helper가 필요하면 먼저 `content/*`, `background/*`, `backup/legacy-panel/*` 중 ownership 위치를 정하고, 정말 공용 core일 때만 `contracts/extension-contract.json`과 `scripts/verify-contracts.js`를 함께 갱신한다.
- hosted `extension-v2/panel/*` feature controller와 Firestore client는 raw `invokePage({ action })` / `invokeRuntime({ action })` 문자열을 직접 들고 있지 않는다. stable page/runtime transport 문자열은 `hosting/extension-v2/panel/extension-capability-client.js` 한곳에만 두고, 나머지 hosted feature 모듈은 semantic capability method만 호출한다.
- 기본 `scripts/verify-legacy-isolation.js`는 active manifest/content뿐 아니라 hosted v2 panel entry가 dead legacy asset(`legacy-panel.css`, `legacy-tools.css`, `prompt-hub-*`)을 다시 로드하지 않는지, active `content/hosted-panel-bridge.js`가 legacy prompt/release/meeting action surface를 다시 열지 않는지도 함께 고정한다.
- `content/panel.js`는 runtime target 선택에서도 feature helper를 직접 고르지 않는다. panel iframe target은 `shared/firebase-config.js`의 `firebaseConfig.panel.resolveRuntime()`를 통해 받아 generic host + broker 역할만 유지한다.
- 현재 `1.0.0` hosted panel UI 변경은 먼저 `hosting/extension-v2/panel/*`에서 해결할 수 있는지 확인하고, `content/panel.js`와 `content/hosted-panel-bridge.js`는 iframe host/bridge 계약 자체가 바뀔 때만 수정한다.
- `content/route-sync.js`와 `content/panel.js`는 실제 버그나 새 요구가 생기기 전까지 다음 기본 리팩토링 대상으로 잡지 않는다.
- 앞으로 panel shell 안에서 새 controller를 더 만드는 기준은 `독립 lifecycle`, `독립 테스트/교체 가치`, `다른 표면 재사용`, `현재 경계로 반복 버그 수정이 어려운 경우`로 제한한다.
- 다른 feature로 읽기 범위를 넓히기 전에는 짧게 왜 확장이 필요한지 설명한다.
- content에서는 파일 길이보다 `독립 DOM`, `스타일`, `이벤트 흐름`, `상태`, `lifecycle` 경계를 먼저 본다.
- 항상 같이 로드되고 함께 수정되는 render/helper/controller 조각은 line count만으로 새 파일로 나누지 않는다.
- 별도 파일이나 별도 진입점은 재사용, lazy loading, 독립 controller 상태, 교체 가능한 UI surface가 있을 때 우선 검토한다.
