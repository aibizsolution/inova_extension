# 기능 명세서

## 1. 목표

이 확장프로그램의 목표는 `i-Nova 더하기`라는 확장 이름 아래, 현재 대화의 질문 탐색과 자주 쓰는 요청 재사용, 여러 사용자가 공유하는 `프롬프트 스토어`, 그리고 수동 배포용 `릴리스 안내`를 `실험실 패널` 안에서 빠르게 처리하게 하는 것입니다.

## 2. 범위

포함 범위는 다음 기능입니다.

- `팝업 On/Off`
- `질문 자동 모으기`
- `우측 슬라이드 패널`
- `대화 안에서 찾기`
- `자주 쓰는 요청`
- `프롬프트 평가/보완`
- `요청 가져오기/내보내기`
- `프롬프트 스토어`
- `릴리스 안내`

제외 범위는 다음과 같습니다.

- 전체 대화 목록 검색
- 계정 공유
- 태그 편집
- 답변까지 포함한 복합 요약
- 요청 자동 전송

## 3. 사용자 흐름

1. 사용자가 툴바 팝업을 연다.
2. `i-Nova에서 사용`과 `질문 자동 모으기`를 켠다.
3. i-Nova 채팅에서 질문을 보낸다.
4. 확장프로그램이 해당 질문을 현재 대화 기준으로 자동으로 모아 보여준다.
5. 오른쪽 슬라이드 패널의 세로 도구 레일에서 `질문`, `요청`, `스토어`, `릴리스` 중 하나를 선택한다.
6. `질문` 도구에서는 현재 대화의 질문 목록과 검색 결과를 보고, 항목을 클릭하면 해당 질문 위치로 이동한다.
7. `요청` 도구에서는 사용자가 저장한 자주 쓰는 요청을 선택해 현재 입력창에 바로 넣는다.
8. `요청` 도구에서는 현재 입력창 프롬프트를 평가해 부족한 점과 보완 프롬프트를 확인한다.
9. `요청` 도구에서는 필요하면 요청을 추가, 수정, 삭제하거나 JSON으로 가져오고 내보낸다.
10. `스토어` 도구에서는 다른 사용자가 등록한 프롬프트를 찾아 좋아요를 누르거나 내 요청으로 가져온다.
11. 사용자는 본인 요청을 스토어에 카테고리와 함께 등록하거나 다시 삭제할 수 있다.
12. `릴리스` 도구에서 현재 버전, 최신 버전, ZIP 설치 방법, 이전 버전 링크를 확인한다.

## 4. UI 요구사항

- 팝업은 기능 상태를 명확하게 보여야 합니다.
- 패널은 화면 오른쪽에 붙는 슬라이드 방식이어야 합니다.
- 패널은 기본 닫힘 상태를 기준으로 하고, 같은 탭 안에서 마지막 선택을 기억해야 합니다.
- 닫힌 상태의 `실험실` 핸들은 사용자가 원하는 높이로 옮길 수 있어야 하고, 위치를 기억해야 합니다.
- 패널 안에는 왼쪽 세로 도구 레일과 오른쪽 작업 영역이 있어야 합니다.
- `질문` 도구, `요청` 도구, `스토어` 도구, `릴리스` 도구는 한 화면에서 바로 전환되어야 하며, 별도 홈 단계는 두지 않습니다.
- `질문` 도구에는 검색 입력, 결과 개수, 목록, 상태 메시지가 있어야 합니다.
- `요청` 도구에는 검색, 추가, 수정, 삭제, 가져오기, 내보내기 UI가 있어야 합니다.
- 대화 입력창 우측 상단에는 현재 입력 프롬프트 평가 버튼이 떠 있어야 합니다.
- 평가 결과는 입력창에 붙는 작은 팝오버에서 요건별 피드백과 보완 프롬프트를 보여줘야 합니다.
- `스토어` 도구에는 검색, 카테고리 필터, 정렬, 목록, 좋아요, 가져오기 UI가 있어야 합니다.
- `스토어` 도구에는 `전체`와 `내 등록` 범위를 전환하는 UI가 있어야 합니다.
- 스토어 항목에는 등록자, 카테고리, 조회수, 가져오기 수, 좋아요 수가 함께 보여야 합니다.
- `릴리스` 도구에는 현재 버전, 최신 배포 여부, ZIP 다운로드, 설치/업데이트 안내, 이전 버전 링크가 있어야 합니다.
- 현재 위치의 질문은 강조 표시가 필요합니다.
- 기존 `대화 검색`과 헷갈릴 수 있는 이름과 아이콘은 피해야 합니다.
- 한국어 사용자 기준으로 영어 라벨과 약어 사용을 최소화해야 합니다.
- `OFF` 상태에서는 핸들과 패널이 모두 숨겨져야 합니다.

## 5. 상태 관리 규칙

- 대화 키는 현재 URL의 `sid`를 사용합니다.
- `chrome.storage.local`에는 설정과 세션 단위 일시 중지만 저장합니다.
- 패널 핸들 위치 같은 UI 선호도는 `uiPreferences`에 저장합니다.
- 전체 설정은 `settings.enabled`와 `settings.autoBookmark`로 관리합니다.
- 세션 단위 중지는 `pausedSessions[sid]`로 관리합니다.
- 현재 선택한 도구는 `uiPreferences.activeTool`에 저장합니다.
- 핸들 위치는 사이트 기준으로 기억하되, 화면 폭 구간에 따라 따로 보정할 수 있어야 합니다.
- 질문 목록 자체는 저장하지 않고, 현재 대화 DOM에서 실시간으로 읽습니다.
- 요청 보관함은 `promptLibrary.items`에 저장합니다.
- 원격 백업 대기 상태와 마지막 동기화 메타는 `cloudSync`에 저장합니다.
- 스토어 목록과 반응 상태는 기본적으로 메모리에서만 관리하고, 원격 지표는 필요할 때만 Functions를 통해 읽고 씁니다.

## 6. 질문 모으기 규칙

- 대상은 `.chat-message--user`로 잡힌 사용자 질문입니다.
- assistant 응답, 시스템 메시지, 아티팩트 설명은 포함하지 않습니다.
- 패널에는 현재 대화에 보이는 질문만 보여야 합니다.
- 세션 이동 중 이전 대화의 질문이 잠깐이라도 섞여 보이지 않도록 대기 상태를 둡니다.
- 좁은 화면에서 항목 클릭 후 원문 확인이 필요하면 패널을 잠시 접어 가림을 줄입니다.

## 7. 요청 보관함 규칙

- 사용자는 요청 항목을 직접 추가, 수정, 삭제할 수 있어야 합니다.
- 각 요청은 `이름`과 `본문`을 가져야 합니다.
- 요청 항목을 선택하면 현재 대화 입력창에 본문을 바로 주입해야 합니다.
- 입력창에 기존 텍스트가 있으면 `덮어쓰기`, `이어붙이기`, `취소` 중 하나를 선택할 수 있어야 합니다.
- 요청 선택은 입력창까지만 주입하고 자동 전송하지 않습니다.
- 현재 입력창 프롬프트를 `맥락`, `목표`, `제약`, `산출물 형식` 기준으로 평가할 수 있어야 합니다.
- 평가 결과에는 요약, 기준별 상태, 보완 포인트, 재사용 가능한 보완 프롬프트가 포함되어야 합니다.
- 평가 결과의 보완 프롬프트는 사용자가 선택해 입력창에 바로 다시 반영할 수 있어야 합니다.
- 요청 가져오기는 JSON 파일 기준으로 동작해야 합니다.
- 요청 가져오기 모드는 `추가`, `병합`, `완전 교체`를 지원해야 합니다.
- `병합`은 같은 요청을 업데이트하고 없는 요청은 추가합니다.
- `완전 교체`는 현재 요청 보관함 전체를 가져온 내용으로 바꿉니다.
- 사용자는 본인 요청을 `스토어 등록`할 수 있어야 합니다.
- 스토어 등록 시 카테고리를 반드시 선택해야 합니다.
- 스토어에 등록된 요청은 로컬 요청 카드에서 `스토어 삭제`로 다시 내릴 수 있어야 합니다.

## 8. 프롬프트 스토어 규칙

- 스토어 등록 대상은 사용자가 직접 만든 요청 항목입니다.
- 스토어에는 `카테고리`, `제목`, `본문`, `등록자`, `조회수`, `가져오기 수`, `좋아요 수`, `등록일`이 보여야 합니다.
- 다른 사용자는 스토어 항목을 `내 요청으로 가져오기` 해서 자신의 요청 보관함에 복사할 수 있어야 합니다.
- 본인이 등록한 스토어 항목은 스토어 화면에서 바로 삭제할 수 있어야 합니다.
- `좋아요`는 사용자별 토글 방식이어야 합니다.
- `조회수`는 상세 내용을 실제로 펼쳐 본 경우에만 올라가야 합니다.
- 스토어 목록은 기본적으로 최신 등록 순을 지원하고, 최소한 좋아요순 또는 가져오기순 정렬도 지원해야 합니다.
- 스토어 데이터는 공용 플랫폼 안의 별도 컬렉션/서브컬렉션으로 분리해야 하며, 요청 보관함 백업 문서와 직접 섞지 않습니다.
- 릴리스 메타는 Hosting의 `latest.json`과 `history.json`으로 분리하고, ZIP 자체는 버전별 파일로 누적 보관해야 합니다.

## 9. 검증 기준

- manifest에 `popup/index.html`, `content/main.js`, `content/panel.css`, `shared/*.js`가 선언되어 있어야 합니다.
- README와 이 문서에는 핵심 기능 키워드가 모두 들어 있어야 합니다.
- 필요한 파일이 빠지면 검증 스크립트가 실패해야 합니다.
- 한 소스 파일이 과도하게 커지면 구조 계약 검증이 실패해야 합니다.

## 10. 수동 확인

- 질문 3개를 보낸 뒤 자동으로 모여 보이는지 본다.
- 대화 안에서 찾기로 각각 찾고 클릭 이동이 되는지 본다.
- `i-Nova에서 사용`과 `질문 자동 모으기`를 끄고 켰을 때 표시 상태가 올바르게 바뀌는지 본다.
- `요청` 도구에서 새 요청을 추가하고 입력창에 바로 넣어 본다.
- 입력창에 내용이 있을 때 `덮어쓰기`와 `이어붙이기`가 각각 기대대로 동작하는지 본다.
- 입력창에 임의 프롬프트를 적고 평가했을 때 요건별 피드백과 보완 프롬프트가 보이는지 본다.
- 평가 결과의 `입력창에 반영`을 눌렀을 때 보완 프롬프트로 교체되는지 본다.
- 요청 보관함을 JSON으로 내보낸 뒤 다시 가져와 `추가`, `병합`, `완전 교체`가 각각 기대대로 동작하는지 본다.
- 요청 카드에서 `스토어 등록`을 눌러 카테고리와 함께 공개되는지 본다.
- `스토어` 도구에서 등록된 항목이 보이고, 좋아요와 가져오기가 각각 동작하는지 본다.
- 다른 브라우저 또는 새 탭에서 `스토어`를 열었을 때 원격 변경분을 무리 없이 반영하는지 본다.
- 닫힌 상태의 `실험실` 핸들을 위아래로 옮긴 뒤 새로고침해도 같은 높이에 유지되는지 본다.
